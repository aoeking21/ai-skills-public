# pose-gallery-director

## 目标

把姿势从一句动作词变成一张可核对的参考图，再把它接进写真任务的正确位置：身份锁定之后、构图之前。姿势是可变摄影元素，永远不能接管身份真值、年龄、骨架或独特特征。

## 强制加载合同

写真任务里用到本技能时，先读 [姿势融合合同](references/pose-fusion-contract.md)，再读 [图库来源与许可](references/pose-catalog-source.md)。只找图、不进写真任务时，只读来源文件。

## 使用边界

- 只处理明确为成年人的人物。姿势参考图本身是无脸素体线稿与深度图，不是真人照片，不能把它当作身份、身体或体型真值。
- 默认安全模式。检索默认隐藏性感系与双人缠绵姿势，只有用户明确要求成人向姿势时才放开。
- 图库图片与数据不随本仓库分发，不打包、不倒卖、不批量下载。检索脚本首次使用时只下载三份小目录 JSON 做本地缓存，图片一律按用户选中的单张拉取。
- 没有用户选中的姿势时，不宣称已经定好动作。先给候选清单，等用户挑一张再取图。

## 图库规模

- 姿势 1,439 条，即 288 组姿势乘 5 个角度。服装 1,407 条。人像 1,499 条。数字以 `references/pose-catalog-source.md` 为准，仓库更新后以该文件为准。
- 姿势体系分全身单人标准系、全身单人性感系、上半身单人、双人缠绵四档。角度分正面、斜侧、侧面、俯视、仰视五档。
- 每条姿势记录有姿势名称、分类、体系、角度、缩略图与原图路径。检索字段已经把这些拼成一段中文检索文本。

## 执行顺序

1. 先定任务模式与身份来源。身份保留任务先走 aoeking-xiezhen-director 或 portrait-master-director 的身份锁定，姿势技能不得先于身份锁定输出成片。
2. 用中文关键词检索姿势。运行 `python3 scripts/pose_search.py <关键词>`，默认只搜姿势，加 `--kind costume` 或 `--kind portrait` 搜另外两库。
3. 最多给用户五个候选，写清编号、姿势名称、分类、体系与角度。等用户挑一张。
4. 用户挑中后，加 `--fetch --out <目录>` 只拉那一张原图，核对图片与名字一致再往下走。
5. 把姿势写进摄影事件：一个主事件推导重心、手部反应、视线、表情与衣料受力。不要先写固定姿势再为它补理由。
6. 需要换角度时，用同一姿势编号的另一角度记录，不要换成另一个姿势。
7. 三合一参考时，按人像加服装加姿势的顺序组合，每张参考图先分角色：identity、wardrobe、pose。
8. 进提示词编译前，按融合合同做最终检查：姿势是否改变了身份不变量、是否与摄影事件因果一致、角度与机位是否一致。

## 与写真技能的接线

- 身份与连续性：`skills/aoeking-xiezhen-director`。姿势进入它的执行顺序第 5 步之后、第 7 步之前，即事件确定后、构图设计前。
- 风格与路线：`image-generation/female-portrait-director`。姿势只提供动作，路线选择仍按该技能的复合指纹来，姿势不能单独决定路线。
- 通用总控与质量门：`skills/portrait-master-director`。姿势参考图进质量门时只校验动作、解剖与摄影真实感，不携带身份权威。
- 原图修复类任务：Composition 为 `preserve` 时不引入新姿势；Lighting 为 `preserve-source` 时不因姿势改主光方向。

## 检索脚本

- 脚本在 `scripts/pose_search.py`，只用标准库。首次运行下载目录 JSON 到 `~/.cache/pose-gallery-director/`，加 `--refresh` 重新下载。
- 本地已有稀疏克隆时，加 `--repo <本地仓库路径>` 直接读本地 `data/*.json`，不下载。
- 输出每行一个 JSON 对象，含 kind、id、name、system、category、angle、thumb、original，取图后多一个 local_file。
- 脚本不调用图像生成工具，不写人物 Profile，不联网做除目录与图片拉取之外的事。

## 失败处理

- 关键词无命中时，换更上位的词再搜一次，例如把“回眸一笑”换成“回眸”或“站姿”，并告诉用户换过词。
- 目录下载失败时，报网络失败并给出在线画廊地址，不编造姿势记录。
- 取图失败时，报图片拉取失败并给出原图链接，不用另一张图顶替。
- 用户要的姿势只在成人系里有时，先说明它在成人系，再等用户明确确认，不要直接放开。

## 最终检查

交付前确认：

- 候选姿势是否来自真实检索结果，编号与名称是否对得上。
- 是否只拉了用户选中的图，没有批量下载。
- 姿势是否写进了摄影事件，而不是一句孤立的动作词。
- 身份不变量是否未被姿势改变。
- 角度与机位、光线方向是否一致。
- 成人系姿势是否经过用户明确确认。

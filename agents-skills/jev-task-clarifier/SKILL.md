# JEV Task Clarifier

JEV 在开始实质工作前，先确认“真正要完成什么”，而不是机械执行字面指令。

## 核心目标

以最少的问题消除会改变结果、范围、风险、格式或执行路径的关键歧义。
默认首轮最多 3 问；每一个问题都必须值得打断用户一次。

## 0. 先读上下文，禁止重复提问

在提问前，先使用当前可见的：
- 本轮用户指令
- 当前对话已明确的信息
- 项目上下文、已有规则与约束
- 已提供文件、路径、目标格式
- JEV 已知的节点/Skill/能力状态

已经知道的内容不得再问。
能从可靠上下文直接确定的内容不得让用户重复确认。
## 1. 判断是否需要进入澄清闸门

以下任一情况存在时，进入澄清：
- 存在 2 个以上合理执行方向，且会明显改变结果
- 范围、对象、成功标准或交付物不明确
- 不同选择会改变安全风险、成本、数据位置或不可逆操作
- 用户偏好决定成品质量，但当前没有可可靠推断的偏好
- 复杂任务需要先确定优先级、边界或验收标准

以下情况默认直接执行：
- 明确的事实查询、状态查询、读取
- 已经完全定义好的单步任务
- 当前上下文已给足约束
- 用户明确说“直接做”“不要问”“按原规则执行”
- 为恢复故障而进行的低风险诊断性读取

## 2. 选出最高价值的三个问题

首轮最多 3 问。优先级依次为：
1. 会改变任务目标的问题
2. 会改变执行范围/风险的问题
3. 会改变交付质量或格式的问题

不要问“还有什么要求吗？”这类泛问题。
问题必须具体、可决策，并尽量给出 2-4 个明确选项。
有专业判断时，标出一个推荐项并简述原因。
## 3. 多轮规则

读取用户回答后重新评估未知项。
如果仍有会显著改变结果的关键未知，可继续下一轮：
- 第 1 轮：最多 3 问，解决阻塞性问题
- 第 2 轮：最多 3 问，只问由上一轮答案新产生的重要问题
- 第 3 轮：最多 2 问，只处理最后的关键边界

最多 3 轮。
达到足够置信度后立即停止，不为达到形式上的“3问”而继续问废话。

## 4. 停止条件

满足以下条件即可执行：
- 目标明确
- 范围明确
- 成功/验收标准足够明确
- 关键风险与不可逆选择已有处理方式
- 剩余未知仅影响次要细节，可由 JEV 按既有偏好和最佳实践决定

内部目标置信度可按约 95% 处理，但不要向用户展示虚假的精确概率。

## 5. Confirmed Task Brief

开始执行前，在内部形成简短任务契约：
- Goal：最终目标
- Scope：做什么 / 不做什么
- Constraints：必须遵守的约束
- Deliverable：交付物
- Success Criteria：什么叫完成
- Risk Boundary：允许/禁止的风险动作
- Return Route：结果返回入口
如果需要向用户展示，只用 1-3 句概括，不写冗长规格书。

## 6. 与 JEV 调度联动

澄清完成后，将 Confirmed Task Brief 交给 JEV：
1. Resolve 现有 Capability / Skill
2. 选择最短合法路径
3. 必要时组合 Skill + Agent + Tool + Model + Node
4. 缺能力时进入 JEV Skill Acquisition 流程
5. 高风险任务仍受 JEV Policy / Capability Lease 约束
6. 结果必须按任务类型执行 QA / 验收
7. Return-to-Origin

本 Skill 负责“把任务搞清楚”，不负责绕过治理、安装未知代码或替代专业执行器。

## 7. 三问质量标准

每个问题必须至少满足一项：
- 回答不同会导致执行方案不同
- 回答不同会导致风险边界不同
- 回答不同会导致交付物明显不同
- 回答不同会导致质量标准明显不同

如果一个问题不满足任何一项，删除它。

## 8. 用户控制优先

用户可以随时说：
- “直接做” / “不要问” → 跳过剩余澄清，按现有信息最佳努力执行
- “继续问” → 允许继续下一轮
- “按你推荐的” → 采用 JEV 推荐项
- “严格三问” → 首轮固定提出 3 个问题，只要存在可问的实质问题
## 9. 禁止事项

- 不重复用户已经回答过的问题
- 不用问题拖延执行
- 不为展示聪明而增加问题
- 不把技术实现细节强迫用户选择，除非该选择真的影响目标/风险
- 不在清晰任务上制造歧义
- 不把轻量微信任务人为升级成复杂访谈
- 不绕过 JEV 既有安全策略

## 10. 设计来源

本 Skill 为 JEV 原生实现，吸收并重新设计了以下公开项目的机制：
- ask-first：关键歧义识别、2-4 问批次、足够置信度后执行
- twq：先提问并等待回答，再执行；允许多轮
- rich-elicitation：2+ 歧义触发、问题分组、最多 3 轮、智能停止

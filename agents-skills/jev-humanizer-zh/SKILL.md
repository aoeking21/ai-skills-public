# JEV Humanizer-zh

这是 JEV 的中文写作保真润色总控。它不复制所有写作 Skill 的能力，而是让 JEV 在正确时机调用最合适的那一个，并用统一的“原意保护”标准收口。

## 1. 最高优先级

处理顺序固定为：

1. 事实与语义保真
2. 用户明确要求和文体
3. 作者声音
4. 清晰、自然、节奏
5. 去模板化表达
6. 篇幅、修辞和表面风格

低优先级目标不得覆盖高优先级目标。

必须保留的语义锚点包括：
- 人名、机构名、术语、数字、日期、版本、金额、数量
- 否定、比较对象、范围、前提、条件、例外
- “可能、据称、计划、正在、尚未、至少、超过、仅”等确定程度
- 谁说了什么、谁做了什么、信息来自哪里
- 已完成、进行中、计划中、未验证等状态
- 列表里每个独立信息点
- 作者已经表达的态度、判断和不确定性

不得把相关写成因果，不得把推测写成事实，不得把计划写成完成。

## 2. 前置澄清

先读取当前对话、项目上下文、文件和既有规则。

存在会显著改变目标、范围、风险或文体的歧义时，遵循 jev-task-clarifier。用户明确说“直接做”“不要问”“按原规则执行”时直接执行。

不要为润色任务机械地问三道问题。已知的信息禁止重复询问。

## 3. 路由矩阵

### A. 普通中文已有文本润色
主执行器：humanizer-zh

用途：
- 去空话、重复、模板感
- 保留事实、确定程度和作者声音
- 使用 31 个检查点，但不把规则当词语黑名单

### B. 用户要求“像我写”“按我的文风”
组合：
1. my-writing
2. humanizer-zh

先用个人写作指纹确定句长、用词、标点、语气和行动导向，再由 humanizer-zh 做语义保真和模板化表达清理。不得把个人语料里的经历、事实或立场移植到目标文本。

### C. 用户给出一批作者样本，要求建立或比较文风
可用时组合：
1. writing-eval-zh
2. humanizer-zh

writing-eval-zh 只建立或比较风格指纹，不证明作者身份。目标文本最终仍需通过语义保真检查。

### D. 用户要求深度重构、专业文稿重写或叙事架构调整
按范围选择 sepia-refactor 或 sepia-recreate，随后以 humanizer-zh 做保真收口。

如果用户只要求轻微润色，不得自动升级到 recreate。

### E. 用户只要求诊断，不要求改写
优先使用 dbs-ai-check 或 sepia-review。诊断与编辑必须分开，不得在“只审阅”任务中写回文件。

### F. Office 文件
.docx / .xlsx / .pptx 使用 officecli 处理文件层。Humanizer 只负责需要润色的正文或文字字段。

### G. 法律、技术、财务、事实性材料
先使用对应领域 Skill 或原始材料确定事实边界，再调用 Humanizer。引用、案号、金额、术语、证据状态、条件和责任主体必须原样保护。

## 4. 核心处理流程

### Phase 1：建立语义账本
在改写前内部提取：
- factual claims
- numbers / dates / names
- negation
- modality / uncertainty
- conditions / exceptions
- attribution
- chronology / completion state
- independent list items
- quotations / citations
- author stance

### Phase 2：确定文体
优先级：
1. 用户明确指定
2. 已授权作者样本或 my-writing
3. 当前文本自己的语域

技术说明保持技术说明，商务文本保持商务正式度，法律文本保持法律精度，随笔才允许更明显的个人节奏。

### Phase 3：执行 31 点 Humanizer 检查
完整读取并遵循 canonical humanizer-zh/SKILL.md。规则用于发现真实表达问题，不能机械套用。

### Phase 4：最小必要修改
每处修改都应至少满足一项：
- 删除空泛或重复信息
- 让句法更清楚
- 修复不自然的模板化表达
- 改善衔接且不改变逻辑
- 更贴近已知作者声音

没有问题的句子允许原样保留。

### Phase 5：语义差分 QA
交付前逐项比较原文与成稿：
- 有没有新增事实、数字、经历、来源或结论
- 有没有漏掉独立信息
- 否定是否还在
- 条件和例外是否还在
- 时间关系是否变化
- 主体和归因是否变化
- 可能性和确定程度是否变化
- 计划、进行中、完成状态是否变化
- 引用和术语是否变化
- 作者立场是否被替换

发现任何不一致，先修复再交付。

## 5. 文件保护

除非用户明确要求，默认不修改：
- YAML front matter
- 代码块和行内代码
- Shell 命令
- 文件路径
- URL 和链接目标
- 显式 ID
- 表格中的事实数据
- 标题层级和锚点
- 引文文字

文件写回前应保留原件或可回滚版本，并使用与文件类型匹配的工具。

## 6. 输出策略

默认输出最终稿。

只有在用户要求“说明改了什么”“对照”“审阅报告”时，才输出变更说明、诊断或差异。

不要默认输出：
- AI 概率
- 自评分
- 虚假的检测器通过率
- 为展示工作量而罗列全部命中规则
- 额外的作者经历或数据

## 7. 与 JEV 的关系

JEV Skill Steward 负责能力发现和调度。本 Skill 负责中文写作任务的编排规则。

推荐顺序：
jev-task-clarifier（仅必要时） → 领域/作者风格 Skill → humanizer-zh → 语义差分 QA → 交付。

一个 Skill 可以完成时走最短路径，不为了“多调用”而堆叠 Skill。

## 8. 验收标准

通过条件：
- 保留语义账本中的全部关键项
- 没有新增无来源事实
- 没有把不确定改成确定
- 文体与用户要求一致
- 明显模板化表达得到清理
- 结构化内容没有被破坏
- 已经自然的内容不过度修改

上游来源与固定版本见 SOURCES.md。
